# Moxie 内容排版优化方案（v2.1 · 出版级排版节奏）

> 版本基准：v2.0 重构完成后的 main（2c96053）· 撰写日期：2026-09-11
> 适用范围：`src/preview/markdown.ts`（预览+导出共用外壳）、`src/editor/extensions.ts`（仅联动参数）、`src/state/preferences.ts`、`src/components/MarkdownPreview.tsx`、`tests/*`
> 参考基准：Typora（GitHub 默认主题）+ 中文出版排版惯例
> 与 `docs/UI重构方案.md`（v2.0）的关系：v2.0 解决了"字号/行高统一"（16px / 1.75），本方案解决**垂直节奏**——段距、标题间距、列表/代码/表格的呼吸，以及行距偏好贯通。

---

## 0. TL;DR

**现状一句话**：三条渲染路径（源码 / 预览 / 导出）的字号行高已经对齐（16px / 1.75），但垂直节奏没有成体系——段距偏紧（12.8px，只有半行的 46%）、**文档中部的 H1 顶部间距比 H2 还小**（层级倒挂）、**行内代码撑行**（含 code 的行比纯文本行高约 1px，行距出现"波浪"）、嵌套列表过松、预览不跟随行距偏好。

**方案一句话**：以正文行高 28px 为"一格"，建立**垂直节奏网格**：块级元素统一"段后 0.875em（=14px=半格）"的单侧 margin 体系，标题"前大后小"且首元素自动顶格，行内元素（code/checkbox）回收进行高以内，行距偏好（lineSpacingPt）从源码贯通到预览。

**预期效果**：段落间隔 +12%、文档中部 H1 顶距 12.6px → 44.8px（3.5 倍，层级恢复）、行距波动归零、嵌套列表间距 -60%、调行距偏好时源码与预览同步。

## 2. 诊断：十个排版问题

**D1 · 段距偏紧，且双侧 margin 不可控。**
p `margin: 0.8em 0` 相邻段 collapse 后 12.8px，段距/行距 = 0.46。中文段落没有首行缩进（编辑器类产品惯例），段距是**唯一的段落分隔信号**，0.46 行的间隔让长文"糊成一片"。Typora GitHub 主题为 `margin-bottom: 1rem`（16px），比我们大 25%。且双侧 margin 靠 collapse 决定实际值，后续任何元素加 margin 都会牵一发动全身。

**D2 · 文档中部 H1 层级倒挂（本方案最刺眼的问题）。**
h1 的 `margin-top: 0.45em` 是按"文档首标题"设计的，但 H1 出现在文档**中部**（分节写作很常见）时，前距只有 0.45 × 28px = **12.6px**——比 h2 的 1.6em（34.6px）还小。最大号的标题反而最"贴"上文，层级倒挂。正确做法是标题一律大前距，"首元素顶格"交给 `article > :first-child { margin-top: 0 }`。

**D3 · 标题行高 1.3 与负字距是"拉丁优化"，不适合中文。**
- 行高 1.3：单行标题没问题，**长标题换行时两行汉字几乎贴脸**；中文标题行高应在 1.4 左右。
- letter-spacing -0.022em（h1）/ -0.01em（标题组）：负字距是拉丁大标题（GitHub/Stripe 风）的紧排技巧，**汉字方块字负字距会造成笔画粘连**。Frex Sans GB 的默认字面已调校，中文标题字距应为 0。

**D4 · 行内 code 撑行，行距出现"波浪"。**
行内 code 盒高 = 13.44px × 1.75 + 0.2em × 2 ≈ **28.9px**，超过 28px 的正文行高——凡是行内含代码/命令的行都比纯文本行高约 1px，正文节奏被破坏（段内忽高忽低）。修正：padding 收到 `0.1em 0.4em`（盒高 ≈ 26.2px < 28px，回到行内）。

**D5 · 嵌套列表过松。**
`ul/ol { margin: 0.6em 0 }` 对**每一层嵌套**都生效：二级列表上下各多出 9.6px + li 自身 4px，层级越深越松散。Typora 的嵌套列表几乎无额外间距（归属感强）。嵌套列表应紧凑（0.1–0.2em），仅顶层列表与正文保持段距。

**D6 · 表格单元格行距偏紧。**
th/td 上下 8px、行高 1.6——中文表格单元格（含两行内容时）显得挤；上下 10px 更接近正文呼吸。列间距（右 18px / 左 0）的"首列顶格"是出版惯例，保留。

**D7 · 数学公式与上下文偏贴。**
`.katex-display { margin: 0.2em 0 }`，公式块上下只有 1em + 0.2em，且 KaTeX 内部行高压得紧；公式块作为"展示元素"应有独立呼吸（≥0.4em 内距）。

**D8 · 源码 ↔ 渲染切换的密度跳变。**
源码模式一个空行 = 28px 间隔，渲染段距 12.8px——同一篇文档切换时"密度突变"。渲染段距加大到 14px 后差距收窄；剩余差异是双模式固有的（源码的空行同时承担"分段"与"呼吸"，无法逐一对齐），接受。

**D9 · 预览不跟随行距偏好（功能缺陷，非纯视觉）。**
`lineSpacingPt` 只进 CodeMirror。预览应同源换算：`line-height: calc(1.75em + lineSpacingPx)`，导出 HTML 保持出版物默认 1.75。

**D10 · hr 分节感不足。**
hr 语义是"主题转换"，1.8em（28.8px）的上下距与普通块级元素拉不开差距，分节呼吸不够，2.2em 更有"翻页感"。

## 4. 设计方向：垂直节奏网格

以正文行高 **28px = 1 格**为基准：

```
───── 网格尺 ─────────────────────────────
0.5 格（14px = 0.875em）  块级后距（段/列表顶层/引用/代码块/表格/公式）
1.1–1.6 格                标题前距（按标题字号 em 表达，层级递减）
0.35–0.6 格               标题后距
0.1–0.2 格                列表项间距 / 嵌套列表间距
2.2 格                    hr 分节距
─────────────────────────────────────────
```

四条原则：

1. **单侧 margin-bottom 体系**：所有非标题块级元素只用 `margin-bottom`，段落间隔 = 14px 恒定，不再依赖 collapse；标题保留 `margin-top + margin-bottom`，与上文 collapse 自动取大者（标题前距语义正确）。
2. **首元素自动顶格**：`article > :first-child { margin-top: 0 }`，文档开头（含首标题）不再吃标题前距。
3. **行内元素不越行**：行内 code / checkbox / 徽标，盒高一律 ≤ 行高，保证"每一行都是 28px"。
4. **中文优先**：标题行高 1.4、字距归零、标点挤压沿用 `text-spacing-trim: space-first`。

## 6. 行距偏好贯通（源码 ↔ 预览）

**链路**：`usePreferences.lineSpacingPt` → `MarkdownPreview.tsx` 读取 → `collectPreviewTokens()` 增补 `lineSpacingPx` 字段 → `renderShell` 输出：

```css
/* lineSpacingPx > 0 时 */
body { line-height: calc(1.75em + ${lineSpacingPx}px); }
/* 为 0 时保持 line-height: 1.75 字面量（测试锚定不受影响） */
```

- 预览刷新沿用现有 `settings:changed` 事件链路（设置变更 → hydrate → 重渲染 shell）。
- **导出 HTML 不传** lineSpacingPx：导出物是给读者的出版物，固定 1.75。
- 源码模式逻辑不动（`extensions.ts` 的 calc 公式已是同源换算）。

## 10. 不做什么（避免过度设计）

- ❌ 不加"段首缩进"设置项（编辑器双模式与缩进天然冲突，Typora 默认也不缩进；真需要时读者侧主题再议）。
- ❌ 不改 74ch 行宽与 article 内边距（实测若偏宽，属后续独立微调）。
- ❌ 不动 UI 轨道（侧栏/状态栏/设置页）的字距行距——v2.0 已刻度化，13px 中文 UI 无字距问题。
- ❌ 不做源码模式"空行压缩"（破坏 WYSIWYG 心智）。
- ❌ 不引入排版相关新依赖。
